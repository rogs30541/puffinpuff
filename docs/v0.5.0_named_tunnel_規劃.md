# PuffinPuff v0.5.0｜Cloudflare Named Tunnel 支援規劃

> **目的**：徹底解決 IG 上傳的 Cloudflare quick tunnel 限流問題（error 1015 / 429）。
> **背景**：v0.4.5 以前用 quick tunnel（無帳號 ad-hoc 隧道）。Cloudflare 對「無帳號 IP」做 rate limit，密集發布會撞牆。v0.4.7 加了退避重試，但只是緩兵之計。
> **目標**：提供穩定、無 IP 限流的替代方案。

---

## 1. Quick Tunnel vs Named Tunnel 對比

| 維度 | Quick Tunnel（現況） | Named Tunnel（v0.5.0 新增） |
|---|---|---|
| 是否需 Cloudflare 帳號 | 不需 | 需要（免費版即可） |
| 公開 URL 形式 | `https://random-xxx.trycloudflare.com`（每次不同） | `https://tunnel.yourdomain.com`（固定）或子網域 |
| IP rate limit | **有**（error 1015，未公開上限） | **無** |
| 啟動速度 | 1-3 秒（每次重建） | 1 秒（重連既有 tunnel） |
| 是否需 DNS | 不需 | 需要（cloudflared 自動寫入） |
| 設定複雜度 | 0（自動） | 中（5-10 分鐘一次性設定） |
| Token 管理 | 不需 | 需要 tunnel token（DPAPI 加密儲存） |
| 適用場景 | 個人偶爾測試 | 長期、密集、生產用 |

**結論**：v0.5.0 不取代 quick tunnel，**並存**——新使用者預設 quick tunnel（零配置），進階使用者可在設定頁切換到 named tunnel。

## 2. Cloudflare 帳號 + Named Tunnel 設定流程（給使用者看的）

### 前置條件
- 一個自己擁有的網域（例：`mememaker-tw.com`）
- 該網域的 DNS 必須由 Cloudflare 託管（不需付費，免費 plan 即可）
  - 沒網域時可改用 Cloudflare 提供的 `*.cfargotunnel.com`，但需 Zero Trust 設定（較複雜，不建議）

### 步驟（網頁版設定，10 分鐘搞定）

1. 開 [https://one.dash.cloudflare.com/](https://one.dash.cloudflare.com/)（Cloudflare Zero Trust dashboard，免費版有 50 user 額度）
2. 左側 → **Networks → Tunnels**
3. 右上 → **Create a tunnel**
4. Connector type 選 **Cloudflared** → Next
5. Tunnel name：例如 `puffinpuff-vvlee` → Save
6. 出現「Install and run a connector」頁面，**最重要**：複製畫面上 token（很長一串，以 `eyJ...` 開頭）
   - 這串 token 等同於密碼，會儲存進 PuffinPuff 後用 DPAPI 加密
7. 跳過 Windows 安裝指令（PuffinPuff 內建 cloudflared）→ Next
8. **Public Hostname** 頁：
   - Subdomain：`puffin`
   - Domain：選你的網域（例 `mememaker-tw.com`）
   - Service Type：`HTTP`
   - URL：`localhost:0`（佔位，PuffinPuff 啟動時會動態覆蓋）
   - 按 **Save tunnel**
9. Cloudflare 自動建 DNS CNAME `puffin.mememaker-tw.com → <tunnel-id>.cfargotunnel.com`

### 在 PuffinPuff 內設定（v0.5.0 新增 UI）

設定頁 → 新增「進階：Cloudflare Named Tunnel」卡片：

```
[ ] 啟用 Named Tunnel（取代 Quick Tunnel）

Tunnel Token：[___________________________________________]
                                                  [貼上] [測試連線]

Public Hostname：[puffin.mememaker-tw.com]
（從 Cloudflare dashboard 複製 hostname）

狀態：
  ✅ Tunnel 連線正常（最後驗證：2026-05-25 16:30）
  ⚠️ Token 已儲存但尚未驗證，按「測試連線」確認

[儲存] [清除]
```

## 3. PuffinPuff 內部技術改動

### 3.1 設定儲存

**DB schema 新增**（migration v8）：

```sql
-- v0.5.0：tunnel 設定
ALTER TABLE app_settings ADD COLUMN tunnel_mode TEXT DEFAULT 'quick';
-- tunnel_mode: 'quick' | 'named-cloudflare' | 'ngrok'

CREATE TABLE IF NOT EXISTS tunnel_configs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  mode TEXT NOT NULL,                    -- 'named-cloudflare' | 'ngrok'
  encrypted_token BLOB NOT NULL,         -- DPAPI 加密
  public_hostname TEXT,                  -- 例 puffin.mememaker-tw.com
  last_verified_at INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 3.2 tunnel.ts 抽象化

從現有單一 `serveFileViaCloudflareTunnel()` 改成：

```ts
// src/main/lib/tunnel/index.ts
export interface TunnelProvider {
  name: 'quick' | 'named-cloudflare' | 'ngrok';
  serve(opts: ServeOptions): Promise<TunneledFile>;
}

export function getActiveTunnelProvider(): TunnelProvider {
  const mode = getAppSetting('tunnel_mode');
  switch (mode) {
    case 'named-cloudflare':
      return new NamedCloudflareTunnelProvider();
    case 'ngrok':
      return new NgrokTunnelProvider();
    case 'quick':
    default:
      return new QuickCloudflareTunnelProvider(); // 現有實作
  }
}
```

各 provider：

- `src/main/lib/tunnel/quickCloudflare.ts`：現有 quick tunnel 邏輯（v0.4.7 退避邏輯保留）
- `src/main/lib/tunnel/namedCloudflare.ts`：
  ```ts
  spawn(bin, ['tunnel', 'run', '--token', token, '--no-autoupdate'])
  ```
  不需從 stdout 抓 URL（hostname 是設定來的）；要動態指定 ingress URL（local HTTP server port）：
  ```ts
  // named tunnel 的 ingress 是「設定時就指定」，但 service URL 可以動態改
  // 方案 A：使用 named tunnel + sidecar HTTP server，URL 是 https://<hostname>/<exposedName>
  ```
  ⚠️ Named tunnel 的 ingress 是預先設定的 hostname → service URL 對應；service URL 一般是 `localhost:80`。我們會把 PuffinPuff 本機 HTTP server 固定 bind 在某個 port（例 33344），named tunnel ingress 指向 `http://localhost:33344`。

  **這意味著：使用者在 Cloudflare 設定時，service URL 不能填 `localhost:0`，要填 `http://localhost:33344`（或我們文件指定的 port）**。

- `src/main/lib/tunnel/ngrok.ts`（可選，v0.5.x 後補）：
  ```ts
  import ngrok from 'ngrok';
  const url = await ngrok.connect({ addr: port, authtoken });
  ```

### 3.3 設定頁 UI（new component）

新增 `src/renderer/src/components/TunnelConfigCard.tsx`：

### 3.4 publish flow 改動

`src/main/ipc/publishHandlers.ts` 的 `runInstagram` / `runFacebook`（碰到要 tunnel 的地方）：

```ts

// 新

```

## 4. 風險 / 邊界條件

### 4.1 Named Tunnel 風險

- **使用者 token 外洩**：DPAPI 加密儲存（與 OAuth token 同等級）
- **使用者 token 過期**：Cloudflare named tunnel token 預設不會自動過期（除非手動 revoke），但連線失敗時要顯示明確錯誤訊息引導重抓
- **使用者改網域 DNS**：DNS 沒對到 → 顯示「Public Hostname 無法解析」錯誤
- **Service URL port 衝突**：PuffinPuff 固定 port 33344 → 如果使用者本機已佔用，要 fallback 或讓使用者改 port

### 4.2 Ngrok 風險（v0.5.x 才做）

- 免費版有每月 1GB 流量、單 endpoint、URL 每次重連都變
- 需要 authtoken
- npm `ngrok` 套件需編譯（platform-specific binary），增加打包大小
