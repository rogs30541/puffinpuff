# v0.9.0 規劃：OAuth 憑證自帶（開源商用版第二塊拼圖）

> 目標：使用者自行提供 Google / Meta / Threads App credentials，
> 不再依賴開發者 bundle 的 `secrets/*.json`。開源使用者 clone 下來就能建置可用的安裝檔。

---

## 1. 現況問題

- `secrets/*.json` 打包進安裝檔（v0.7.2 起在 asar.unpacked，**任何拿到安裝檔的人都看得到 app_secret**）
- ⚠ **安全問題**：repo 公開後，GitHub Releases 上的安裝檔含開發者的 Meta app_secret
- 開源使用者 clone repo 後沒有 secrets → 無法使用 OAuth 功能

## 2. 解法：三層憑證來源（DB 優先 → 檔案 fallback → 友善報錯）

```
loadCredentialsJson(provider):
  1. DB oauth_credentials 表（DPAPI 加密）← 使用者在設定頁貼的
  2. secrets/<provider>_oauth.json 檔案 ← 開發者本機 build 的 fallback
     （讀到時自動匯入 DB，之後 DB 優先）
  3. 都沒有 → throw 友善錯誤，指引使用者到設定頁
```

- **開發者自己（VVLEE）**：本機 build 有 secrets 檔 → 行為完全不變，首次啟動自動匯入 DB
- **開源使用者**：clone 沒有 secrets → 設定頁貼自己的 App credentials（一次性）
- **公開發布的安裝檔**：build 時排除 secrets → 乾淨、無機密

## 3. 變更清單

| 項目 | 內容 |
|------|------|
| DB v12 | `oauth_credentials` 表（provider PK, encrypted_json BLOB）|
| 新檔 | `src/main/lib/credentialsStore.ts` — loadCredentialsJson / save / delete / status |
| 改 10 檔 | 13 個 `readFileSync(secrets/...)` 呼叫點全部改走 credentialsStore |
| 新 IPC | `credentials:getStatus / save / delete` |
| 新 UI | SettingsPage「OAuth 憑證（自帶 App）」卡片：三區塊 + 貼 JSON + 教學連結 |
| 打包 | electron-builder 的 `secrets/*.json` 維持 optional glob（無檔案時 build 照常過）|

## 4. 各 provider 必要欄位（儲存時驗證）

- **google**：`installed.client_id`、`installed.client_secret`
- **meta**：`app_id`、`app_secret`、`api_version`（config_id / redirect_uri / scopes 可選，沿用預設）
- **threads**：`app_id`、`app_secret`、`api_version`、`redirect_uri`

## 5. 使用者自建 App 指南（設定頁內嵌摘要 + 連結）

- Google：console.cloud.google.com → 建專案 → OAuth 同意畫面 → Desktop client → 下載 JSON 貼上
- Meta：developers.facebook.com → 建 Business App → FB Login for Business → 抄 app_id/secret
- Threads：同 Meta App 啟用 Threads API → 獨立 app_id/secret

## 6. 既有安裝的遷移

- v0.9.0 首次啟動：secrets 檔案還在（v0.8.x 裝的）→ 自動匯入 DB
- 之後升級到「無 bundle secrets」的版本也不受影響（DB 已有）
